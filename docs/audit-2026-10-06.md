## Critical and High, cross-area, in the order to fix

### 1. 🔴 Authentication bypass via percent-encoded path (Critical)

`apps/backend/src/api/http.ts:71,106-110`. The `onRequest` hook tests the raw `req.url` against a prefix regex; the router matches the decoded path. Reproduced in-memory:

```
/workspaces      status 401 authChecked true  handlerRan false
/%77orkspaces    status 200 authChecked false handlerRan true
```

Impact: anyone who reaches the port (any tailnet peer; any local process while `MOMENTUM_HOST` is loopback, as `.env` sets today) can `POST /%77orkspaces/momentum/chats` and start a Claude Code run with `bypassPermissions` on the host, or call `PUT /%73ettings`, reset projects, approve feed items, drive the MCP endpoint and the voice relay.

Fix: default-deny on the *matched* route. Mark `POST /session`, `/openapi.json` and the static plugin as `config: { public: true }`; everything else requires a session. Add an e2e that sends encoded paths.

### 2. 🔴 Every run inherits the harness environment, including the database password (High)

`packages/runs/src/session.ts:185-201` passes no `env`; the SDK defaults to `{...process.env}` (`sdk.mjs:136,142`); `apps/backend/src/config.ts:6` loads `.env` into the process. Runs are `permissionMode: 'bypassPermissions'` and model-driven, so a prompt injection in any summarized repository file can `psql $DATABASE_URL` to forge a session row, replace the credential hash, or edit any workspace index.

Fix: build a minimal child environment in `spawnLimited` (PATH, SystemRoot, USERPROFILE, APPDATA, TEMP) and never forward `DATABASE_URL` or `MOMENTUM_*`.

### 3. 🔴 Runs can rewrite and auto-deploy the harness itself (High, design-accepted)

`guard.ts:336-340` → `git.ts:139-144,376-388`: `land()` adds everything in the checkout; only `knowledge-graph/` needs approval. The harness repo is a workspace, `tsx watch` under `service/serve.ps1` restarts on change, and `.claude/settings.json` hooks run in every run. An injected harness run can edit `auth.ts` or the branch hook and have it live in seconds.

Fix: in the harness workspace refuse landing outside `knowledge-graph/` (at least `apps/**`, `packages/**`, `scripts/**`, `.claude/**`, `*.ps1`), or serve from a pinned checkout the user advances.

### 4. 🔴 Summarization handoff is trusted, not verified (High)

`runner.ts:765` marks artifacts as handed to summarization *before* the Stop hook asks the model to invoke the sub-agent; `guard.ts:333-338,203` then excludes them from `artifactsChanged`. If the model ignores the request or the sub-agent fails, those artifacts land unsummarized and are never flagged `artifact_ahead`.

Fix: at `transaction()` time, drop from `handled` any artifact with no covering entity in `byArtifact()` or the checkout.

### 5. 🔴 A transient git error disables a project (High)

`orchestrator.ts:144`: `nonLinear().catch(e => [e.message])` turns a `GitError` (lock held longer than 5 s, `git.ts:29`) into a "not one straight line" reason and switches the project off with a `project_disabled` event.

Fix: disable only on the three real reasons `nonLinear` returns; log and retry on `GitError`.

### 6. 🔴 Run state machine is implicit and racy (High)

`runner.ts:182-185` sets status unconditionally. (a) `send()` on an ended chat (`:560-574`) is not serialized: two messages read `finished`, both launch, `active.set` overwrites one, a Claude process leaks. (b) `kill()` on a queued run (`:586-590`) races `launchRun` (`:356-361`); a killed run can start. (c) `finish()` reads the row outside the `try` (`:628`); a DB blip leaks the active entry, chokidar watcher and worktree, and `run_ended` never fires.

Fix: `transition(ws, id, { from: RunStatus[], to })` as `update … where status = any($from) returning id`, throwing on zero rows; one per-run serial queue around start/send/kill/finish.

### 7. 🔴 The CLI runs orchestration in a second process (High)

`cli.ts:44` → `putSettings` → `orchestrator.enable` → `tick()`, which indexes main lines and starts queued runs with an empty `active` map, while a live server shares the database; `cli.ts:84-85` then exits. Per-process caches and `guard.exclusive` do not cover it.

Fix: the CLI talks to the running server over `/settings` or `/mcp`, or `createMomentum({ orchestrate: false })`.

### 8. 🔴 Scripted Claude stand-in keys on harness prose copied by hand (High, tests)

`e2e/support/scripted.ts:181-187,406,414` substring-match strings whose originals live in `hooks.ts:17,20,61,84` and `runner.ts:114,527-528,793`. A wording change makes 30+ scenarios fall back to `Done.` and pass vacuously or fail late.

Fix: export the markers (or a machine-readable turn header) from one module under `apps/backend/src`; import it in the stand-in; unit-test `kindOf`.

### 9. 🔴 Core behaviour has no fast tests (High, tests)

Zero unit tests for `guard.ts` (568 lines), `runner.ts` (800), `orchestrator.ts` (314), `approval.ts` (309), `api/http.ts`, `auth.ts`, `voice/*`, `packages/runs/git.ts` (410). The e2e tier needs Windows, Firefox, Postgres, procgov and a signed-in account. Session expiry is tested nowhere. Pure candidates today: `SequenceTracker.accept`, `graphBuildPrompt`, `withContext`, `git.nonLinear/mergesBetween/land`, `usage-fit.splitRun`.

### 10. 🔴 Metrics tables grow on every transaction and have no indexes (High, schema)

`db.ts:176-221`: `attention_metric`, `understanding_metric`, `implementation_metric`, `agent_metric` have no usable index; `guard.ts:560-561` inserts two rows per `recordMetrics`, which runs from both `indexNow` and `transaction`. `/metrics` then range-scans them (`metrics.ts:63-64,84,101,125`) and `standingBy` (`metrics.ts:111-117`) scans `entity_state` once per bucket, 24 to 30 times per request.

Fix: the index list under Data schema; write understanding/implementation rows only when values changed; one windowed query for `standingBy`.

### 11. 🔴 Feed card palette frozen at import (High, app)

`apps/app/src/app/(tabs)/feed.tsx:37-46` evaluates `C.surface`/`C.line` into a module constant, which `theme.ts:90-91` explicitly forbids. Dark mode shows a light card and never updates on toggle.

### 12. 🔴 Voice control socket: duplicate connect and unbounded reconnect (High, app)

`lib/voice.ts:41-68`: the `if (control) return` guard precedes the `await`, so two mounts in one commit open two sockets; each orphan reconnects every 3 s; with voice off the server closes with 1011 and the client still retries forever, costing a handshake plus an auth query each time.
